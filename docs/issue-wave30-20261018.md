# Fourth Observable runtime prototype: native-stream semantics — draft 2026-10-18

Issue #10: prototype truly stream-native backpressure as a distinct experiment from direct callbacks, Future/await pull and channel/select models.

## Correctness contract
- `subscribe` is cold by default: producer begins only when demand/consumer subscription is admitted.
- Demand is bounded; `next` cannot allocate unbounded buffering or bypass backpressure.
- Subscriber cancellation atomically prevents new user-value publication, releases reserved credits once, then wakes blocked producer/consumer.
- Completion/error is terminal and delivered once after earlier accepted values; no reentrancy or synchronously thrown callback invocation may bypass cancellation ordering.
- The source's actor `state { ... }` and `handle_state`/ `using` read-write loans remain the only persistent guest-owned actor storage.

## Race and interleaving fixtures
1. request(0) → no producer emission; request(1) → one item and no extra pull.
2. cancel vs producer publish at every reservation/commit step → one ownership outcome, zero leaks.
3. terminal before subscribe → one terminal, no deadlock.
4. map/filter/take(1) over a bounded source → one committed item, producer teardown once.
5. subscriber callback reentrancy → deferred deterministic notification rather than Zalgo behavior.
6. multiple subscribers demand independently; no cross-subscriber mutable payload escape.

**Status:** candidate semantics only; no fourth stream-runtime implementation or performance comparison is claimed by this branch.
